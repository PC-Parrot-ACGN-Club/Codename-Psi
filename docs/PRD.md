# PRD：桌面端连锁对战游戏

**文档定位：** 立项时制定的产品契约。描述开发至少需要覆盖的目标、范围与验收方向；实际开发中可按情况修订，修订时同步更新本文档与关联设计。  
**版本：** 1.0  
**语言：** 简体中文、English  
**平台：** Linux

## 1. 产品定位

一款桌面端双人连锁消除竞技游戏。玩家操控成对落下的彩色球组成连锁、向对手发送垃圾球，并通过 Fever 机制展开攻防。任一方棋盘达到溢出判定线时，该局失败。

首版提供本地双人和单人对战 AI，使用纯色矢量图形完成全部可玩内容。局域网 P2P 对战作为第二阶段交付。完整对局流程、规则轮廓、Fever 分支和配置要求见[玩法设计](gameplay.md)；角色、美术、名称、音效和文案全部使用原创内容。

## 2. 目标与范围

### 2.1 成功目标

- 在 Linux 完成稳定的 BO3 本地对战。
- 让两位玩家使用键盘或手柄完成完整的原作风格连锁、抵消垃圾和 Fever 对抗。
- 提供遵循相同游戏规则的实时单难度 AI。
- 让两台同一局域网内的设备可通过手动输入 IP 与端口完成一场 P2P BO3 对战。

### 2.2 版本划分

| 阶段 | 交付内容 |
| --- | --- |
| R1：本地可玩版 | 本地双人、对战 AI、完整常规/Fever 规则、BO3、菜单、设置、双语、双角色、占位语音、键盘与手柄 |
| R2：局域网联机 | 创建/加入房间、手动 IP:端口、确定性同步、断线判负、网络状态提示 |

### 2.3 当前不包含

- 互联网匹配、房间列表、NAT 穿透、观战、重连和跨网络存档。
- 排位、账号、排行榜、战绩系统、单人剧情或关卡。
- 多个竞技规则模式、道具、特殊球种和付费内容。
- 角色立绘、动画、正式配音与商业级音效素材。
- 面向玩家的对局回放、录像回看或分享功能。文档与工程中的「回放 / 输入日志」仅指开发与 CI 用的确定性验证手段（固定种子 + 输入序列 → 状态校验和），不进入产品界面。

## 3. 玩法引用

完整玩法以[玩法设计](gameplay.md)为准，涵盖棋盘和输入、连锁结算、攻击与连续抵消、Fever、全消、BO3 流程及规则配置。PRD 只保留以下产品约束：

- R1 提供 Fever 连锁对战，R2 在完全相同的规则状态机上提供局域网 P2P 对战。
- 游戏界面持续显示盘面、下一球对、垃圾、Fever 信息、角色标识和比赛比分。
- 规则数值和题面集中写入版本化配置，默认采用 Fever 1/2 主机/PC 原作数值（来源与引用见[玩法设计](gameplay.md)）；开发侧可用固定随机种子与输入日志做确定性回归。
- 本地对局提供暂停、重开和退出；局域网对局以断线判负结束比赛。

## 4. 模式、角色与 AI

### 4.1 模式

模式选择页只提供一种竞技规则：Fever 对战。玩家从以下对手类型中选择：

- 单人：玩家对实时 AI。
- 本地双人：两位玩家共用一台设备。
- AI 对战 AI：双方均由 AI 驱动，玩家不参与操作。它服务于表现层的观察与调试——一局可以在无人操作的情况下走完，从而完整看到演出。
- 局域网对战：R2 解锁；一方创建房间，另一方输入主机 `IP:端口` 加入。

### 4.2 角色与语音

- 首版提供两位可选原创角色。角色选择影响昵称、配色、UI 标识、语音触发和玩法文档定义的掉落组；角色掉落组在开局前锁定。
- 为开局、消除、连锁、进入 Fever、获胜和失败定义稳定的语音事件接口。
- 首版不随包分发音频资源，语音与音效事件以静音实现：事件接口、触发时机和音量设置全部生效，只是没有声源。后续加入正式音频文件无需改动游戏逻辑。

### 4.3 AI

- AI 使用与人类相同的盘面、候选球序列、落下和结算规则；它通过合法输入行动。
- AI 每个球对生成时基于己方盘面、公开对手盘面、待接收垃圾和 Fever 状态选择落点与旋转。
- 单难度以可完成基础连锁、进行垃圾抵消、识别即将溢出危险、使用 Fever 机会为验收基线。
- AI 决策只通过合法输入行动：可读信息限于人类同款可见状态，落子与节奏遵循同一规则接口。

## 5. 界面与交互

### 5.1 页面

页面布局、常驻对局信息、动效、无障碍和表现层接口见[表现与 UI 设计](presentation.md)。

| 页面 | 必需内容 |
| --- | --- |
| 主菜单 | 开始游戏、设置、退出 |
| 模式选择 | 单人、本地双人、AI 对战 AI、局域网对战（R2）、返回 |
| 角色选择 | 两个角色、玩家位置、确认/返回 |
| 设置 | 语言、主音量、音效音量、全屏/窗口、键盘映射、手柄映射、手柄震动、动画强度、色觉辅助 |
| 游戏界面 | 左右盘面、下一组球、垃圾提示、Fever 信息、角色标识、比分、暂停菜单（仅本地） |
| 赛果界面 | 胜者、BO3 比分、再来一局、返回主菜单 |

### 5.2 输入

- P1 与 P2 分别保存独立的键盘映射。每位玩家至少映射左、右、软降、硬降、顺时针旋转、逆时针旋转、确认和返回/暂停。
- 默认键位应避免 P1/P2 冲突；配置页面允许捕获并替换任意支持按键。
- 支持常见 XInput 与 SDL 兼容手柄。按键映射可保存为单独的手柄配置，支持震动开关。
- 输入配置发生冲突时，界面明确提示并要求玩家确认覆盖或重新绑定。

### 5.3 本地化与视觉

- 所有面向玩家的文本使用键值本地化；首版提供 `zh-CN` 和 `en`，缺失键回退至英文。
- 首版以渲染库内建图元绘制：纯色球、简单边框、文字、进度条与几何图标；无外部美术资源时仍可启动并完成可玩流程。
- 色彩、图标和文字共同表达状态；垃圾、Fever、胜负等关键信息同时提供非颜色线索。

## 6. 网络需求

详细的 crate 划分、引擎集成、网络协议、数据格式、测试和 CI 方案见 [TDD](TDD.md)。

### 6.1 局域网 P2P（R2）

- 主机创建房间后监听可配置端口并显示本机 IP 与端口；加入方手动输入该地址。
- 连接建立时校验游戏版本、规则配置版本、角色选择和随机种子。校验失败时阻止开局并显示可理解的原因。
- 对局同步保证双方对相同输入得到相同结果，并能识别和报告状态不一致。
- 网络界面显示连接中、已连接、同步中与断线状态。连接断开立即判定断线方输掉当前比赛，双方返回赛果页。
- R2 不提供暂停、重连、房间浏览和 NAT 穿透。

## 7. 数据与配置

- 玩家设置在本机持久化：语言、窗口模式、音量、键盘映射、手柄映射、震动开关、动画强度、色觉辅助。
- 规则配置单独版本化，至少包含得分表、垃圾换算、Fever 参数、题面表、球色集合和下落时序。
- 角色定义以数据驱动方式保存显示名、本地化键、颜色、语音事件资源键和 UI 图标参数。

## 8. 验收标准

### R1

- Linux 可启动并完成一场本地 BO3。
- 本地双人和人机模式均可从主菜单进入、完成角色选择、由某一方先胜两局完成比赛并回到赛果页。
- 四连消除、连锁、重力、垃圾抵消、垃圾落下、溢出判负、全消、Fever 进入/退出及预设题面均通过规则单元测试和可视化对局验证。
- 相同随机种子和输入日志在重复运行时产生相同的小局结果、分数、垃圾数量和 Fever 状态。
- AI 可在连续 20 场测试对局中完成合法操作并正常结束比赛，过程中没有无响应、非法落子或状态修改。
- 可在设置页切换中英文、音量、窗口模式、震动、动画强度、色觉辅助与任意键盘/手柄映射；重启后设置保留。

### R2

- 两台同一局域网内的目标设备可以通过手动输入 `IP:端口` 建立连接并完成 BO3。
- 双端以同一规则版本和种子开始对局，连续 10 场测试无状态校验不一致。
- 对局任一方断开网络连接后，另一方在合理的超时内看到断线判负结果。

## 9. 风险与实施优先级

Fever 原始数值和题面按 Wiki 参考剖面录入配置，并用可复现的确定性验证样本校准。确定性规则引擎应先于 AI 和网络完成，确保 AI 仿真、开发用输入日志回归与局域网同步复用同一套状态机。优先顺序为：规则引擎与单元测试、单盘交互、双盘垃圾/Fever、菜单与设置、AI、本地 BO3、局域网同步。

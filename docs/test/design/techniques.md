# 测试用例设计方法参考

**状态：** 生效  
**适用范围：** 测试点拆分、测试数据选择与预期结果设计

测试设计方法回答“用什么方式系统地选择输入、状态和场景”。Test Level、Concern 与 Domain 回答测试范围、验证目的和业务职责；三者共同记录在测试用例中。

## 1. 选择方法

| 被测行为信号 | 优先方法 | 产出 |
| --- | --- | --- |
| 输入可分成若干行为相同的集合 | 等价类划分 | 每类一个或多个代表数据。 |
| 存在上下限、阈值、区间或容量 | 边界值分析 | 边界及相邻值。 |
| 结果由多个布尔或离散条件共同决定 | 判定表 | 有业务意义的条件组合与结果。 |
| 对象具有有限状态与转换规则 | 状态迁移 | 状态、事件、转换、守卫条件与结果。 |
| 多个参数形成大量组合 | 成对组合或覆盖数组 | 指定覆盖强度的代表组合。 |
| 行为由完整操作链路体现 | 场景法 | 主路径、分支与中断场景。 |
| 规则存在跨输入持续成立的约束 | 性质测试 | 输入生成器、不变量与收缩目标。 |
| 输入变换后结果具有确定关系 | 变形测试 | 原始输入、变换与结果关系。 |
| 历史行为需要稳定保护 | Characterization Test | 当前可观察基线与证据状态。 |
| 缺陷容易集中在经验性薄弱点 | 错误猜测 | 具名风险与针对性案例。 |

一个测试点通常选择一项主方法；复杂规则可组合两项方法。例如，Fever 题面分支使用判定表，状态进出使用状态迁移。

## 2. 常用方法

### 2.1 等价类划分

将输入按预期行为划分为等价集合，每个集合选择代表值。集合依据来自格式、范围、状态、权限或业务规则。

| 输入集合 | Psi 示例 | 用例数据 |
| --- | --- | --- |
| 有效规则配置 | schema 与版本匹配的 `RuleProfile` | 已知规则版本与完整字段。 |
| 结构缺失 | 缺少必填字段的配置 | 缺失字段名与最小其余字段。 |
| 语义冲突 | 数值满足类型但违反规则约束 | 题面引用未知掉落组。 |

记录每个集合的划分依据，使后续字段扩展可以判断归属和新增集合。

### 2.2 边界值分析

围绕每条边界选择边界值及相邻值。离散整数常用 `min`、`min + 1`、`max - 1`、`max`、`max + 1`；区间和枚举按规则定义选择相邻代表值。

| 边界 | Psi 示例 | 代表数据 |
| --- | --- | --- |
| 棋盘列范围 | 左右移动 | 最左列、次左列、最右列、次右列。 |
| 消除阈值 | 同色连通球数 | 3、4、5 个球。 |
| BO3 胜场 | 比赛结束判定 | 0、1、2 场胜利。 |
| 垃圾单次落下上限 | 垃圾结算 | 上限前、上限值、上限后。 |

### 2.3 判定表

列出影响结果的条件、条件取值和预期动作。条件较多时，优先保留具有不同业务结果的组合。

```markdown
| 条件：连锁发生 | 条件：待接收垃圾 | 条件：Fever 量表已满 | 预期结果 |
| --- | --- | --- | --- |
| 是 | 有 | 是 | 抵消垃圾并在安全点进入 Fever |
| 是 | 有 | 否 | 抵消垃圾并继续对局 |
| 否 | 有 | 否 | 垃圾按规则落下 |
```

适合攻击抵消、Fever 题面结果、菜单入口条件和连接握手结果。

### 2.4 状态迁移

将对象表示为状态集合与事件集合，列出每条允许转换的守卫条件和可观察结果。针对状态机，测试每个状态的主要事件、边界事件和重复事件。

```markdown
| 当前状态 | 事件 | 守卫条件 | 下一状态 | 可观察结果 |
| --- | --- | --- | --- | --- |
| Normal | 结算完成 | Fever 量表满 | Fever | 保存普通盘并生成题面 |
| Fever | 时间归零 | 存活 | Normal | 恢复普通盘与垃圾队列 |
| RoundOver | 下一局开始 | 比赛仍未结束 | Normal | 初始化下一小局 |
```

适合 `MatchState`、客户端页面状态和网络会话生命周期。

### 2.5 成对组合与覆盖数组

多个参数共同影响结果时，先定义参数及取值，再选择覆盖各参数对的组合。该方法适合规则版本、角色、输入设备和模式的组合验证。

```markdown
| 组合 | 规则版本 | 角色 | 模式 | 输入来源 |
| --- | --- | --- | --- | --- |
| A | v1 | 角色 A | 本地双人 | 键盘 |
| B | v1 | 角色 B | 单人 | 手柄 |
| C | v2 | 角色 A | 局域网 | 远端 tick 输入 |
```

组合矩阵先经产品规则筛选，再选择覆盖集。每个组合保留选择理由。

### 2.6 场景法

以玩家或系统的完整目标为中心，沿事件顺序设计主路径、关键分支和中断场景。每一步写出参与模块、刺激、状态变化和可观察结果。

```markdown
场景：完成一场本地 BO3

1. 从主菜单选择本地双人。
2. 双方完成角色选择并进入小局。
3. 驱动对局直到一方获得两场胜利。
4. 验证赛果显示胜者、比分与下一步操作。
```

场景法适合 System，也适合短的 Component Integration 协作链。

### 2.7 性质测试

将规则写成对大量输入持续成立的不变量，并以生成器产生棋盘、输入序列或配置组合。失败样本收缩为最小可复现数据，纳入回归用例。

| 性质 | Psi 示例 |
| --- | --- |
| 守恒 | 同一结算中，棋盘球数变化等于移除、落入与生成的规则结果。 |
| 范围 | 坐标始终位于棋盘定义范围内。 |
| 合法性 | AI 输出始终属于当前状态允许的输入集合。 |
| 确定性 | 相同初始状态和输入序列导出相同 checksum。 |

### 2.8 变形测试

为缺少精确预期值的复杂计算定义输入变换与结果关系。变换前后的关系成为断言。

| 输入变换 | 预期关系 | Psi 示例 |
| --- | --- | --- |
| 相同初始状态重复执行 | 结果一致 | 相同 seed 与输入日志产生相同 checksum。 |
| 输入序列拆分并连续执行 | 状态等价 | 连续 tick 与分段推进产生相同 `MatchState`。 |
| 交换双方镜像输入 | 结果镜像 | 对称规则配置下，双方棋盘和得分对应交换。 |

### 2.9 Characterization Test

当当前行为具备保护价值且 Test Basis 处于 `Unknown` 时，记录稳定的输入、环境和可观察输出。用例标明行为基线与证据状态；设计确认后同步更新预期。

### 2.10 错误猜测

以领域经验提出高风险刺激，并在用例中写明风险来源。Psi 的常见方向包括连续输入、相同 tick 内双方结算、空或部分配置、极端棋盘布局、seed 边界、快照恢复、断线与重复事件。

## 3. 方法记录模板

```markdown
### 方法：<等价类 / 边界值 / 判定表 / 状态迁移 / 场景法 / 其他>

**被测行为：** <行为>
**选择理由：** <行为特征与风险>
**输入模型：** <集合、边界、条件、状态或参数>
**代表数据：** <具体数值、seed、fixture 或输入序列>
**预期结果：** <可判定结果>
**关联用例：** TC-<编号>
```

## 4. 组合规则

优先使用能够直接表达风险的最小方法组合：

- 规则公式：等价类 + 边界值；多条件公式补充判定表。
- 状态机：状态迁移；涉及完整业务目标时补充场景法。
- 多参数配置：等价类或边界值确定各参数取值，再使用成对组合选择组合集。
- 随机与演进状态：固定样本或性质测试；结果关系明确时补充变形测试。
- 历史行为保护：Characterization Test，并保留 Test Basis 证据状态。

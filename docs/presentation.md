# 表现与 UI 设计

**文档定位：** 立项时制定的表现与 UI 契约。描述对局界面至少应传达的信息、默认布局与反馈边界；视觉与动效细节可在开发中迭代，迭代时同步更新本文档与设置项。  
**关联：** [PRD](PRD.md)、[玩法设计](gameplay.md)、[TDD](TDD.md)

## 1. 目标与原则

表现层让玩家在一个注视点内读懂自己的操作空间、对手压力、下一手风险和比赛进程。它从 `MatchState` 的确定性快照派生；规则状态只由规则层推进。

Fever 对战需要常驻这些信息：每位玩家的棋盘、下落组、下一组、待接收垃圾、Fever 量表、Fever 时间、Fever 题面进度和比赛比分。Fever 进入时普通垃圾队列转为背景层，Fever 期间的新垃圾进入第二队列；双队列状态应有清晰的视觉区分。[Fever 规则](https://puyonexus.com/wiki/Fever_%28rule%29) [Nuisance queue](https://puyonexus.com/wiki/Nuisance_queue)

视觉风格采用原创的“实验室信号面板”：深色背景、饱和纯色球、细线网格、圆角状态芯片和高对比文字。角色是抽象的头像徽章与标识图形，不使用既有作品的角色形象、名称或标志。

## 2. 比赛界面

### 2.1 1920 × 1080 预设布局

```text
┌──────────┬──────────────┬─────────────┬──────────────┬──────────┐
│          │              │ ROUND · BO3 │              │          │
│          │ P1 垃圾一行  ├─────────────┤ P2 垃圾一行  │          │
│ P1 圆框  ├──────────────┤ P1/P2 NEXT  ├──────────────┤ P2 圆框  │
│ ⌀320     │ P1 棋盘 6×12 │ 各 3 手     │ P2 棋盘 6×12 │ ⌀320     │
│          │ 活动组/危险线│             │ 危险线/活动组│          │
│ 角色名条 │ CHAIN / 攻击 │ P1/P2 Fever │ CHAIN / 攻击 │ 角色名条 │
│          │              │ BO 星牌     │              │          │
│          ├──────────────┼─────────────┼──────────────┤          │
│          │ P1 分数      │             │ P2 分数      │          │
└──────────┴──────────────┴─────────────┴──────────────┴──────────┘
    394           386           360           386          394
```

- 画面横向分五列：外侧立柱、棋盘、中央通道、棋盘、外侧立柱，宽度依次为 394 / 386 / 360 / 386 / 394，合计 1920。两块棋盘等宽、镜像排列，向画面中心靠拢，中间只隔一条通道；棋盘是玩家的主要注视区，占据画面中部而非贴边。
- 棋盘 6 × 12 格，格边长 60、格距 2、内边距 8，单块 386 × 758。
- 垃圾队列压缩为棋盘正上方的一行：分级图标加总数。Fever 待接收与普通待接收同处该行，靠配色区分。
- 分数位于棋盘正下方，使用大号描边数字，与棋盘等宽对齐。
- 中央通道自上而下承载：局次与比分、双方 NEXT 各 3 手、双方 Fever 面板、BO 星牌。通道不承载攻防演出。
- 外侧立柱承载圆框角色图与角色名条（见 §4.5）。立柱是画面上唯一为角色表现保留的区域。
- 倒计时、`READY` / `GO`、`FEVER!`、`Oh no!!`、`WIN` / `LOSE` 属全屏大字层（见 §4.6），常驻版面不为它们保留位置。
- 下一组显示至少 3 手：第一手最大，第二和第三手缩小；每手展示 `DropSet` 形状和颜色布局。角色掉落组是实质玩法信息，预览必须展示形状而非只显示颜色。[掉落组定义](https://puyonexus.com/wiki/Dropset)

### 2.2 分辨率范围

R1 **只采用一种固定画布：`1920 × 1080`、`16:9`**。窗口与全屏均按该画布渲染；显示器比例或分辨率不一致时等比缩放并留边（letterbox / pillarbox），不重排 UI。

首版范围限于上述单一画布。多套预设分辨率会引入布局分叉与重排成本，当前不规划第二套；若以后增加预设，为其单独设计并验收对应布局。

## 3. 规则事实到视觉状态的映射

| 规则状态 / 事件 | 应显示 | 动效与反馈 |
| --- | --- | --- |
| `Falling` | 活动掉落组、轴心标记、下三手预览 | 软降提高下落节奏；硬降显示短暂落点闪光。 |
| `Resolving` | 当前连锁数、被移除球、攻击估算 | 每连一轮显示 `CHAIN n`，镜头和棋盘保持静止，球体缩放后淡出。 |
| 攻击抵消 | 本方抵消量、剩余待接收垃圾 | 两条队列的数字当场变化；抵消不另起文字，减少的待接收量就是抵消量。 |
| 垃圾入队 | 精确数量、等级图标、预计落下时机 | 外侧队列脉冲一次；队列满屏风险触发边框警示。 |
| 垃圾落下 | 落下行数与列序 | 从队列向棋盘分批落下；落点加入短暂阴影。 |
| Fever 量表增长 | 第 n/7 格、获得原因 | 逐格点亮；第 7 格有 150–250ms 的蓄能动画。 |
| `Fever` 进入 | Fever 标签、秒数、等级/题面目标、双垃圾队列 | 普通队列降低亮度并后移；Fever 队列置前；棋盘切换使用全屏外侧光带。 |
| Fever 题面成功 | 达成连锁、下一题面等级 | `TARGET +1`；下一题面从底部逐格落入。 |
| Fever 题面全消 | 全消、时间奖励、题面 +2 | 显示 `ALL CLEAR`、`+5 s`、`TARGET +2` 三个独立标签。 |
| Fever 结束 | 剩余 Fever 队列并回普通队列 | 光带退场；普通棋盘回到前景；合并数量在队列旁显示。 |
| `RoundOver` | 胜负方、败因、局分 | 冻结规则画面，胜方使用主色边框，进入 1.5 秒结算停留。 |
| `RoundOver`（同时失败） | 双方败因、局分不变、本局重打 | 冻结规则画面，两侧使用同一中性边框，进入 1.5 秒结算停留。 |
| 网络断线 | 断线方、超时状态、判负结果 | 将“连接中 / 已连接 / 同步中 / 已断线”写成文字状态与图标。 |

全消与 Fever 的视觉拆分遵循规则效果：普通场全消提供预设 4 连和 Fever 时间奖励；Fever 内全消提升下一题面并提供时间奖励。[All clear](https://puyonexus.com/wiki/All_clear)

### 3.1 角色演出层

双方各一个原创圆框角色图，位于棋盘外侧的立柱（见 §4.5）。演出在各自框内完成：两框相距超过半个画面宽，相向位移读不出碰撞，因此角色不做朝画面中心的推进。攻防的**信息**由棋盘内的 `CHAIN n` 与两条垃圾队列的数字承担，角色演出承担**状态与气氛**，两者不互相替代。

Wiki 能确认 Fever 2 与 15th 的 DS 角色图包含攻击、抵消、受击、胜利、失败/危险与 Fever 等状态素材；角色图库将这些资源标注为 `Attacking Portrait`、`Offsetting Portrait`、`Damage Portrait`、`Winning Portrait` 和 `Losing/Danger Portrait`。[Amitie 图库](https://puyonexus.com/wiki/Amitie/Gallery) [Klug 图库](https://puyonexus.com/wiki/Klug/Gallery) 圆框位置、运动词汇、分档阈值与持续时间没有文字化的 Wiki 规则说明，本节将它们定义为本项目的原创表现层规范。

| 规则事实 | 圆框运动 | 立绘 |
| --- | --- | --- |
| 待机 | 上下飘浮，持续循环 | 待机姿态 |
| 每个 `ClearCommit` | 一次性上跳并回落，逐步各一次，不按连锁数分档 | 进攻姿态 |
| 末连的 `ClearCommit`，且总连锁 ≥ 2 | 与该步上跳同刻 | 按总连锁数取分档 cut-in，压在版面上，整条连锁只出一次 |
| 进入垃圾不足一行 | 无 | 不变 |
| 进入垃圾达一行 | 下沉并衰减振动 | 防御姿态 |
| 进入垃圾达三行 | 深沉并高频振动 | 防御姿态，立绘掉出环外压住名条 |
| 本方优势 | 绕中心小幅摇摆，持续循环 | 优势姿态 |
| 接近溢出 | 边框分段警示 | 紧张姿态 |
| Fever | 环色转为高能色并脉动，持续循环 | Fever 姿态 |
| 全消 | 一次性庆祝动作 | 进攻姿态 |
| 胜 / 负 | 胜：连续小跳；负：整框下沉出画 | 胜利 / 失败姿态 |

运动分两类，实现上不可混为一谈：**循环运动**（飘浮、摇摆、脉动）由状态驱动，进入即播、离开即停；**一次性运动**（上跳、受击）由事件驱动，播完回到循环运动的基线。

**一次性运动的时长必须短于最短的一个连锁步**（`ClearPreview` 加最短重力，见[玩法设计](gameplay.md)）。满足这一条，逐步演出天然不重叠，连锁再长也不需要打断与排队。

cut-in 压在版面上、允许盖住棋盘：它出现时对局处于 `Resolving`，玩家手上没有活动组，控制权要等结算跑完、下一组出生才交回。**「本连是否末连」由规则层在提交时前瞻得出并写入该连的已提交事实**，表现层只读——规则计算不放到表现层。

受击分档阈值与 cut-in 分档阈值写入角色表现数据，不写成常量：档位边界是手感项，调档不应改代码。垃圾图标的分级与受击分档共用同一套阈值语义。

优势状态通过 `pending_garbage`、`overflow_risk`、本次结算的净攻击和 Fever 状态计算；它表达当前局势，不能用于影响掉落组、攻击、AI 或网络同步。演出仅在确认帧的 `ChainResolved`、`GarbageQueued`、`FeverEntered`、`AllClear`、`RoundEnded` 事件上触发，回滚不会产生重复演出。

## 4. 常驻组件

### 4.1 棋盘

- 格线透明度低于球体边缘，落子位置清晰，避免棋盘成为噪声。
- 普通球默认只用纯色填充：消去只看颜色，球内符号对玩法没有贡献，去掉后盘面读取更快。开启“色觉辅助”设置后每种颜色额外获得一个互不相同的内部符号，作为不依赖色相的第二线索。垃圾球使用中性灰与“阻塞”纹理，其标记不受该设置影响——它不是第六种颜色，而是另一类球；Fever 题面中的关键触发球增加轮廓提示。
- 溢出判定格使用细虚线和“危险线”文字；球接近时提高该列的亮度和震动反馈强度。
- 活动组带 1 格宽的投影轮廓，锁定后轮廓立即消失。投影是操作辅助，不进入确定性验证状态、截图对比基准和最终规则状态。
- `CHAIN n` 画在棋盘区域内的左上角，随连锁逐步更新，位置跟着玩家的注视点走。攻击量与抵消量不另写文字：它们已经是两条垃圾队列的数字变化，重复命名只会在对局最忙的时刻多出一处要读的东西。全消这类没有别处可去的事实仍落在同一位置。

### 4.2 NEXT 与掉落组信息

- 每个预览格显示整个下落组，包含 I、L/J、O 形状与单色/双色布局。预览格使用与棋盘相同的彩色格子，颜色与形状均取自该手牌本身，玩家不需要把预览换算成棋盘上的球；组未占据的位置留空，使轮廓可读。
- 掉落组信息只在角色选择页呈现：把 16 手序列展示为 4 × 4 缩略格，并用 2/3/4 球统计帮助玩家判断风格。对局中不再单列掉落组标识——牌序的实物形态已由 NEXT 的 3 手预览表达，标识本身对操作没有贡献。
- 对局中只展示未来 3 手，防止过多信息压缩棋盘。

### 4.3 垃圾队列

- 队列同时显示精确数量和分级图标；图标采用原创几何符号，数量保持可读。
- 普通队列的状态文案为“待接收”；Fever 中冻结的普通队列改为“普通场暂存”，降低对比度；Fever 队列标为“Fever 待接收”。
- 队列使用 1、6、30、180、360、720、1440 的单位生成图标组合，并在相邻位置显示总数。该组单位来自系列垃圾预警语义。[Nuisance queue](https://puyonexus.com/wiki/Nuisance_queue)

### 4.4 Fever 面板

- 7 格量表在中央通道内呈现为一条横向分段条，填充动作逐格发生；文字同时显示 `x / 7`。面板整体压缩到通道宽度内，与 NEXT 共用同一列。
- 进入 Fever 后，面板切换为剩余秒数和题面目标，例如 `FEVER 18.4 s · TARGET 6`。
- 计时器以数字、环形进度和阈值颜色共同表达；低于 5 秒时增加“即将结束”文字标签。
- 题面预设连锁以棋盘中的半透明起始标记呈现，避免玩家把它误读为普通场残留球。

### 4.5 外侧立柱的圆框角色图

- 圆框直径 320，位于棋盘外侧立柱、纵向居中偏下。立绘允许画到环外——环是装饰而非裁剪框，头发、四肢与道具都可以溢出。
- 圆框下方是角色名条，取 roster 的本地化显示名，底色对应玩家身份。
- 每个角色至少提供待机、进攻、抵消、防御、紧张、Fever、胜利和失败八个姿态，另按连锁分档提供 cut-in 立绘。
- 演出层持续展示最近一次确认的攻防结果，新的连锁事件覆盖旧事件。高连锁期间连锁数逐轮更新，圆框逐轮起跳。
- 圆框运动与姿态切换按 §3.1 触发，不提供开关：R1 只实现一套演出方案，两档动画强度下运动与姿态切换都保留，低强度只缩减幅度。连锁数、攻击量与抵消量画在棋盘内，因此演出层不承担唯一的信息传达职责。

### 4.6 全屏大字层

- 倒计时、`READY` / `GO`、`FEVER!`、`Oh no!!`、`WIN` / `LOSE` 共用同一层，居中大字带描边，压在棋盘与中央通道之上。
- 该层的各状态互斥出现，常驻版面不为它们保留位置——它们出现时也不该被别的元素挤压。
- 连锁 cut-in 不属于本层：它压在棋盘上但不占满全屏，归 §3.1。

## 5. 页面流程

```text
启动
  → 主菜单
    → 模式选择
      → 角色选择（掉落组卡片）
        → 本地：赛前确认 → 倒计时 → 对局 → 赛果
        → AI：难度确认 → 倒计时 → 对局 → 赛果
        → LAN：创建 / 加入 → 握手与同步 → 赛前确认 → 对局 → 赛果
    → 设置
```

| 页面 | 关键内容 | 主操作 |
| --- | --- | --- |
| 主菜单 | 开始、设置、退出 | 焦点卡片、确认、返回。 |
| 模式选择 | 单人、本地双人、LAN、R2 状态说明 | 选模式。 |
| 角色选择 | 角色徽章、配色、掉落组 16 手缩略预览、控制器槽位 | 选角色、确认、返回。 |
| 赛前确认 | 双方角色、掉落组、RuleProfile 版本、BO3、网络状态 | 双方确认或取消。 |
| LAN 创建 / 加入 | IP、端口、主机本机地址、连接阶段、失败原因 | 创建、输入地址、加入、取消。 |
| 设置 | 语言、音量、窗口、键位、手柄、震动、动画强度、色觉辅助 | 编辑并保存。 |
| 暂停（本地） | 继续、重开、设置、返回主菜单 | 恢复或结束。 |
| 赛果 | 获胜者、局分、断线原因或胜负原因、再来一局、返回 | 再赛或返回。 |

## 6. 动效、声音与性能边界

- 所有落下、消除、连锁和垃圾动画从规则事件与时间戳驱动；回滚后只呈现最新快照，声音只由确认帧事件触发。
- 一次连锁的每个消除轮保留可读节拍：命中 → 缩放/闪光 → 移除 → 重力 → 下一轮。玩家必须能数清连锁数与垃圾变化。
- Fever 入场使用背景色、边框光带和面板切换三层反馈；三层相互独立，任一层缺失时文字状态仍完整传达。
- 震动按连锁、垃圾落下、Fever 进入和胜负提供短促模式；设置页支持单独关闭。
- 同屏动效遵守对象上限；大量垃圾和高连锁优先合并粒子、数字和音效事件，保持 60Hz 规则 tick 与 UI 响应。

### 6.1 Resolve 阶段投影

结算节拍由[玩法设计：结算计算与阶段提交](gameplay.md#结算计算与阶段提交)以固定规则 tick 提供。表现层不维护能够阻塞规则的独立结算状态，也不向规则层发送动画完成通知。

```text
ResolutionView
├─ phase
├─ chain_index
├─ elapsed_ticks
├─ duration_ticks
├─ clear_cells[]
└─ gravity_moves[] { cell, from, to }
```

| 规则阶段 | 表现行为 |
| --- | --- |
| `ClearPreview` | 先静止若干 tick，再对 `clear_cells` 播放命中、缩放、闪光与淡出；动画进度按扣掉停顿后的剩余 tick 计 |
| `ClearCommit` | 移除对应渲染实体，触发已确认的本轮消除、连锁、攻击音画事件 |
| `Gravity` | 先静止若干 tick，再按等加速度插值：整批共用一条加速度曲线，落差最大的那颗在阶段末落地，落差小的更早落地并停住。不自行决定落地时间 |
| `ScanNext` | 对齐规则快照并准备下一轮；没有下一轮时结束连锁显示 |
| `Settlement` | 展示最终连锁、抵消、Fever、垃圾或失败结果 |

每个有时长的阶段以几 tick 的静止开始：消除先顿一下再播消除动画，落下先顿一下再走。停顿从该阶段自己的 tick 里支出，不额外增加时长，因此规则提交的 tick 不受影响；动画按扣掉停顿后的剩余 tick 插值。没有这段停顿时，消除的尾帧与落下的首帧相接、落下的尾帧与下一步相接，任何一步都读不出「已经结束」。

同一批下落的球共用一条加速度曲线，而不是各自把自己的落差拉伸到整个阶段——后者会让同批球呈现互不相同的速度，并且每一颗都拖到阶段末才落地。

渲染落后于规则进度时直接采样最新阶段；跨过阶段边界时以最新规则快照重建盘面，不要求补播所有中间帧。动画强度设置可以减少粒子、镜头、闪光和插值复杂度，但不能改变 `duration_ticks`、规则事件 tick、下一组生成时机、Fever 时间或攻击到达时间。

本地非回滚对局可以在 `ClearCommit` 立即播放声音。网络回滚对局只对确认后的 `(match_tick, ordinal)` 事件播放一次声音与震动；预测阶段的棋盘动画可随最新快照重建。

## 7. 无障碍与本地化

- 垃圾、Fever、危险线和双方身份均提供至少两种线索，不依赖设置。普通球的第二线索由“色觉辅助”设置提供：默认关闭，开启后每种颜色获得互不相同的内部符号。默认调色板不保证在色觉障碍下可分辨，因此该设置是普通球唯一的非色相线索来源，不能省略。
- 所有关键数字采用等宽数字样式：分数、垃圾数量、Fever 秒数、目标连锁、比分和网络延迟。
- 焦点顺序、确认/返回、键盘与手柄操作在所有菜单一致；焦点状态有高对比轮廓和读屏标签。
- `zh-CN` 与 `en` 使用同一布局约束；动态文案预留长度，数字信息保持固定位置。

## 8. 实现接口

客户端按以下只读接口构建 UI：

```text
MatchPresentationSnapshot
  players[2]:
    board, active_drop, next_drops[3], drop_set_id
    score, pending_garbage, fever_garbage
    fever_gauge, fever_time, fever_target, fever_state
    overflow_risk, chain_count
  match: round, wins, phase, result
  connection: phase, ping, disconnect_reason
  momentum: net_attack, pressure, advantage_side

PresentationEvent
  id: (match_tick, ordinal)
  DropLocked | ChainLinkStarted | ChainLinkCleared | ChainResolved
  GravityCompleted | GarbageQueued | GarbageFell
  FeverGaugeFilled | FeverEntered | FeverPuzzleAdvanced
  AllClear | FeverEnded | RoundEnded | ConnectionChanged
  MomentumChanged
```

`MatchPresentationSnapshot` 包含当前 `ResolutionView`，可在任意帧重建 UI；`PresentationEvent` 只驱动可丢弃的动画和已确认的音频/震动。该约束满足回滚同步、开发用确定性验证与无窗口规则测试。

## 9. 验收清单

1. 任何对局阶段都能从单帧截图识别双方棋盘、比分、下一组、待接收垃圾、Fever 量表/时间和当前胜负状态。
2. Fever 中能同时识别冻结的普通队列与活跃的 Fever 队列；普通场恢复时能读到合并后的垃圾数量。
3. 角色选择页能在确认前展示 16 手掉落组结构；对局 NEXT 与已选 `DropSet` 一致。
4. 低于 5 秒、接近溢出、待接收垃圾和断线状态均同时使用文字与非颜色线索。
5. 在唯一固定画布 1920 × 1080 的窗口与全屏模式中，两块棋盘、NEXT、Fever 面板、垃圾行、分数与外侧立柱的圆框角色图都保持完整可读；非 16:9 显示器仅留边、不重排。
6. 高连锁、垃圾落下与 Fever 切换期间规则 tick 保持 60Hz，动效不改变规则结论。
7. Resolve 动画能够只依赖规则快照和阶段进度重建；跳帧、关闭动效或网络回滚均不改变清除提交、攻击到达和下一组生成的 tick。
